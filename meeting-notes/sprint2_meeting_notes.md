## Discussion Summary

### 1. Fact-Finding Techniques
The team discussed the formal fact-finding techniques required for the project and agreed to use the following methods:

- **Survey / Questionnaire**
  - Surveys will be distributed to tourists and tourism service providers.
  - Responses will be collected and analysed to identify common user requirements and expectations.
  - Statistical summaries and anonymised responses will be documented.

- **Competitive Analysis**
  - Existing tourism platforms such as Booking.com, Airbnb, and Tripadvisor will be analysed.
  - Feature comparison matrices, screenshots, and usability observations will be prepared.
  - Strengths, weaknesses, and missing features will be identified to improve the proposed system.

All research artefacts will be stored in the `documents/research` folder.

## SRS Structure Discussion

The team reviewed the required Software Requirements Specification (SRS) structure and confirmed the following sections:

### 1. Introduction
- Purpose and Scope
- Definitions, Acronyms, and Abbreviations
- References
- Document Overview

### 2. Overall Description
- Product Perspective
- User Classes and Characteristics
- Operating Environment
- Design Constraints
- Assumptions and Dependencies

### 3. System Analysis
- Fact-Finding Techniques Used
- Existing System Analysis
- Use Case Diagram
- Use Case Descriptions
- Activity Diagrams
- System Sequence Diagrams

### 4. Functional Requirements
- Numbered Functional Requirements (FR-01, FR-02, etc.)
- Requirement priorities
- Sources and verification methods

### 5. Non-Functional Requirements
- Performance Requirements
- Security Requirements
- Reliability and Availability
- Usability Requirements
- Scalability Requirements
- Maintainability Requirements

## Key Decisions
- The SRS document will follow the provided academic structure strictly.
- Surveys and competitive analysis will be used as the main fact-finding techniques.
- Personas will be created for Tourist, Hotel Owner, Transport Provider, Tourist Guide, and Admin.
- Functional and non-functional requirements will be documented separately for clarity.
- Competitive analysis findings will be integrated into system analysis.
